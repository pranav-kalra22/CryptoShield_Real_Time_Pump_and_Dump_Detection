# Security Policy

## Supported Versions

Security fixes and maintenance patches are applied to the active development branch:

| Version | Supported          |
| ------- | ------------------ |
| `main`  | :white_check_mark: |
| < 1.0   | :x:                |

---

## Reporting a Vulnerability

The CryptoShield team takes security seriously. If you discover a security vulnerability (e.g., credential leaks, deserialization flaws, injection vectors, or unhandled socket vulnerabilities), please report it responsibly:

1. **Do NOT open a public issue** on GitHub.
2. Report the vulnerability privately by using [GitHub Security Advisories](https://github.com/pranav-kalra22/CryptoShield_Real_Time_Pump_and_Dump_Detection/security/advisories/new) or by emailing the project maintainer directly.
3. Include:
   - Type of issue (e.g., buffer overflow, SQL injection, remote code execution)
   - Component affected (`consumer.py`, `producer.py`, `dashboard.py`, `detection_engine.py`)
   - Step-by-step reproduction instructions or a Proof of Concept (PoC)
   - Impact assessment

### Our Commitment

- We will acknowledge receipt of your vulnerability report within 48 hours.
- We will provide a timeline for assessing the severity and rolling out a patch.
- Once resolved, we will publish an advisory crediting your responsible disclosure (unless you prefer anonymity).
